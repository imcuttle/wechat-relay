# WeChat Relay · 产品宣传片 — Treatment

Style: Living Screencast（活体实机录屏）· 1920×1080 · 30 fps · ~46 s · 中文旁白（edge-tts）+ 原创配乐 · 字幕烧录 + `.srt`

## 1. 三个候选结构

1. **会议中的一小时（选中）**：开场就是一串系统通知砸下来"工作群 99+"，人不在电脑前。WeChat Relay 被打开，像素小信使"小驿"从 App 图标里钻出来，依次完成：看（识别）→ 筛（规则）→ 写（智能体起草）→ 等（审核）。光标（用户）回来，一次点击，消息送达。结尾窗口变暗，小驿在「已发送回复」计数上睡着。
   - 优点：一个主体（小驿）、一个目标（替你接住消息）、一个转折（"发不发，由你决定"——控制权回到用户），产品四个核心能力按真实数据流顺序出现。
2. **左右对比赛跑**：左窗"手动回复"，右窗"Relay"，同一批消息比谁先清空。问题：把产品讲成"更快"，但它真正卖点是"后台 + 可控"，而且分屏让 UI 太小。
3. **一条消息的旅程**：镜头跟随一条"报价单什么时候能发？"从微信截图进入 OCR、规则、模型、草稿、发出。清晰但缺少"人"，没有转折，结尾无力。

选 1：开场有钩子（通知雪崩，3 秒内），中段是节奏变化最大的"工作流"，转折处有一段静音 + 聚光冻结，结尾呼应开场（开场 99+ 未读 → 结尾 0 未读、计数 +1、小驿入睡）。

## 2. Logline 与弧线

**Logline**：你在开会，微信在爆；WeChat Relay 在后台替你看、替你筛、替你写——但最后那一下"发送"，永远留给你。

- Setup（0–8 s）：通知雪崩，未读飙升；Relay 被打开，小驿诞生。
- Development（8–29 s）：小驿沿识别框奔跑读消息 → 在规则标签上跳格子 → 拿像素铅笔写草稿（4× 延时标签）。
- Turn（29–35 s）：音乐抽空到房间底噪，镜头推到"审核后发送"，晕影冻结："发不发，由你决定。"
- Ending（35–46 s）：光标点「发送」，草稿状态变「已发送」，消息气泡飞进聊天窗，小驿骑着它出画又跳回；拉远到全窗，「已发送回复 1」，小驿在数字上睡着，窗口标题 github.com/imcuttle/wechat-relay。

## 3. Benchmark

- **Screen Studio 风格的产品录屏**（自动跟随光标缩放、点击推近）——学：镜头永远跟着"事情发生的地方"；缩放 ≥ 1、平滑弹簧。不学：其壁纸、配色、界面。
- **Apple Guided Tour**——学：一句话一个功能、语速平稳、画面先于旁白半拍出现。不学：任何具体镜头和音乐。
- **Duolingo 吉祥物动作**——学：预备—动作—缓冲、落地挤压回弹。不学：角色造型。

## 4. 主角与世界

- **界面**：按 `src/renderer` 真实重绘：左侧 208px Sider（实时监控 / 会话记录 / 待审核 / 回复规则 / 智能体 / 模型 / Harness / 工具 / MCP / 提示词 / 运行日志 / YAML 配置），顶栏 Tag「Cua Driver 就绪」「微信 pid」、Segmented「审核后发送 / 自动发送」、Switch「自动操作」、按钮「开始监听 / 停止监听」。Ant Design 浅色主题，主色 #1677ff，品牌绿 #07c160，背景 #f5f6f8。所有文案取自源码。
- **聊天窗**：在「实时监控」卡片里出现的是一个**虚构的聊天客户端截图**（中性灰白 + 绿色自己气泡，无任何真实品牌标识），会话名虚构：「产品组」「王总」「家庭群」「快递通知」。
- **小驿**：12×12 方像素信使，一个带小帽檐的对话气泡身体，两只脚；颜色 #ff7a1a 亮橙（UI 中不用作大面积色），深棕 #3b1d0a 描边。表情靠眼睛；道具：像素铅笔、"!"、星星、Zzz、尘土。
- **光标**：macOS 箭头，弹簧路径，点击时轻压。

## 7. Cue map

- 速度 100 BPM（1 拍 = 0.6 s，1 小节 = 2.4 s），4/4。
- §A 0–4.8：只有通知 "叮" 叠成节奏 + 低频脉冲，每张通知落在 8 分音符上，越来越密（加速）。
- §B 4.8–9.2：鼓组进入（紧鼓刷 + 电贝斯），小驿出生时 chiptune 方波第一次出现（三音上行）；落在产品名 = 第 3 小节强拍。
- §C 9.2–23.6：完整乐队（电钢 + 贝斯 + 紧鼓 + 钟琴点缀），chiptune 方波与电钢对答；小驿每次跳 Tag 都有一个方波音，音高随 Tag 上行。
- §D 23.6–29.0：鼓抽掉一半，延时段 hi-hat 16 分音符 + 方波琶音（"工作中"）。
- §E 29.0–34.6：音乐抽空 → 房间底噪 0.8 s → 单个长垫音（pad）在"由你决定"下；第一声是光标点击（全片最重要的声音之一）。
- §F 34.6–46.0：点击后军鼓 fill + 镲进入完整乐队一小节，气泡飞入 "嗖"+通知 "叮"；40.2 起逐渐减为电钢 + 方波低八度慢速重复（入睡），最后一个方波音落在小驿闭眼上，留 1.2 s 余韵。

## 8. 声音设计表

| 段落 | 底噪 | 主要拟音 | 音乐状态 |
|---|---|---|---|
| A 通知雪崩 | 会议室空调底噪（低通噪声） | 通知 "叮"（不同音高）、卡片落下轻 "啪" | 低频脉冲 + 叮声节奏 |
| B 诞生 | 室内底噪 | 甩镜 whoosh、图标弹跳、窗口弹出 pop、8-bit 爬出/跳跃/落地 | 鼓 + 贝斯进入，方波首现 |
| C 识别 | 室内底噪 | 光标点击、识别框 "滴"、8-bit 脚步、数字跳动 tick | 全乐队 |
| C 规则 | 室内底噪 | 甩镜 whoosh、8-bit 跳跃 ×3（音高上行）、行高亮 click | 全乐队 + 方波对答 |
| D 起草 | 室内底噪 | 像素铅笔沙沙（8-bit 噪声）、键盘轻击（打字节奏） | 半鼓 + 方波琶音 |
| E 承诺 | 仅底噪 → 垫音 | 无（静音），之后单声点击 | 抽空 → 长垫音 |
| F 送达 | 室内底噪 | 点击、whoosh、气泡 pop、通知 ding、8-bit 落地 | fill + 镲 → 渐弱 → 摇篮曲式方波 |

两次真正静音：§A→§B 交界前 0.25 s（甩镜前吸气）、§E 0.8 s。
声音转场：J-cut——通知 "叮" 在甩到 App 前提前进入；L-cut——点击发送的回响跨入拉远镜头。
